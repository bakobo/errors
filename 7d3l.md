- 2026-08-28T18:43Z Raised from bakobo/mdoc-interop 2026-08-28, where it was originally filed as tick 7myp. Relocated here because the work is this repo's, not that one's.

mdoc-interop is the estate's first JVM repo. dev/standards/error-codes.md puts grammar enforcement, the prefix matcher and the catalog pipeline in this package, and says plainly that a per-repo reimplementation 'will disagree with its siblings at exactly the edge cases that matter'. A Kotlin repo cannot import any of it.

What mdoc-interop copied, in src/main/kotlin/com/bakobo/mdoc/ErrorCode.kt: the closed first-descriptor set (10 entries, copied 2026-08-28) and the token grammar. Deliberately NOT the matcher -- the consumer of those codes is on the Python side of a CLI boundary, so matching stays in one place. That narrowing is recorded as mdoc-interop's this.i @bi533d, as a tension rather than a solved problem.

Two consequences for this repo:

1. The descriptor set can drift from taxonomy.py with nothing to notice. A generated JSON export of the taxonomy that any language can read would fix it -- mdoc-interop could then reconcile its copy against a fetched artifact in a test.

2. The catalog pipeline extracts codes by static analysis of PYTHON source, so the ~50 codes mdoc-interop now declares are invisible to index.json and to the errors MCP. A code exists that the catalog says does not. That is worse than the drift risk, because the catalog is what the standard points people at.

mdoc-interop's codes are all under prefixes this repo already knows (e.input., e.proof., e.rule., e.party., e.state., e.feature., e.self.), so nothing about the taxonomy needs to change -- only its portability and the extractor's reach.
